# Robot code rules for AI agents (FRC 5110)

## Project
- WPILib 2026.2.1, roboRIO, Java, command-based. Do not use 2027 or SystemCore APIs.
- Use docs.wpilib.org/en/stable, not /en/latest.
- Map of the code: docs/code-structure.md. Critical subsystem and command docs: docs/subsystems/ and docs/commands/.
- The swerve drivetrain is generated by CTRE Tuner X. Don't hand-edit or rename constants in src/main/java/frc/robot/generated/TunerConstants.java; say in the PR if it needs regenerating.

## Rules
- Check APIs against existing code, build.gradle, and vendordeps/. Don't invent vendor APIs.
- One change per pull request. Don't change vendordeps/, build.gradle, or .github/ unless the issue asks.
- Keep constants in Constants.java and put units in names or comments (meters, radians, volts). New CAN ID constants end in _CAN_ID.
- Flag at the top of the PR description any change to CAN IDs, motor direction, current limits, or soft limits.
- If you change a critical subsystem or command, update its doc in docs/ in the same pull request.
- Build with ./gradlew build if you can run commands. It also updates docs/code-structure.md; commit that file. If you can't build, say so in the PR.

## Pull request description
Use the team template: What changed, Why, How it was tested, Anything reviewers should check. Under How it was tested, list what to test in simulation and on the robot.

## Code Review Rules
- Flag wrong units, motor inversions, duplicate CAN IDs, missing current or soft limits, commands missing subsystem requirements, and blocking calls (Thread.sleep, long loops) in periodic code.
- Flag any change to vendordeps/, build.gradle, or .github/.
